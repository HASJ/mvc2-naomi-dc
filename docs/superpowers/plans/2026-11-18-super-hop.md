# Super Hop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pressing `1`, `2` or `3` while a superjump (or an air or wall jump that follows one) is rising eases the rise to 0 over 5 frames, so the player picks the hop height.

**Architecture:** One shared routine, `pl_hop_ck` in `src/pl_sub.c`, called from `pl_sjump_ctrl` (superjump air, air attacks, air jumps) and from `act_jump_air` (wall jumps). It is gated on `sjump_flag != 0`, so every superjump state qualifies (ground, launcher-chase, air recovery, tag-in) and a normal jump never does. The ramp multiplies the current rise speed, so it needs no stored launch speed.

**Tech Stack:** C decomp built by the PC port (MSYS2 MINGW32, CMake/Ninja, SDL3). No C test harness exists, so each task's test is a headless trace run (see Task 1).

**Spec:** `docs/superpowers/specs/2026-11-18-super-hop-design.md` (read its "Corrections found while planning" section; it overrides earlier text).

## Global Constraints

- `HOP_STOP_FRAMES = 5`. Universal constants, no per-character tables.
- Any superjump state can hop (user decision): the gate is `sjump_flag != 0` plus a rising `spd.y > 0`. That includes ground superjumps, launcher-chase superjumps, air recovery and tag-in superjumps. A normal jump (`sjump_flag == 0`) never hops.
- Only `1`/`2`/`3` (`KEY_DOWN` in `pl_sw_new`) starts a stop. An air attack, or any other button, never changes the rise (user decision).
- The computer (`cpu_flag`) is excluded.
- Felicia's wall jump (`TBL_TJUMP`) is excluded.
- The ramp only lowers a positive `spd.y`; it writes nothing once `spd.y <= 0`.
- New state is carved from the unused tail `unk_55d[]` of `PLAYER_WORK` (`include/pl_work.h`). `sizeof(PLAYER_WORK)` stays `0x5a4`, outside the `CHAR_PART` copy range (0xdc-0x19c).
- Unconditional in shared `src/`: no `HOST_PORT` guard on the gameplay change. The trace logging is `HOST_PORT`-only.
- After every build, install into `ports/build-dist/` (`cmake --build ports/build`, then `cmake --install ports/build --prefix ports/build-dist`, with `C:\msys64\mingw32\bin` first in `PATH`).
- Headless runs: use `.agent/rules/headless-test.md` (workspace root), minimized, never focused. Always `pwsh`, never `powershell`.
- Commits: one logical change each. No `Co-Authored-By` trailer.

## Review Focus

- A pure `2` with no forward/back held must stop the rise (`pl_sjump_ctrl` returns early in that case). Pinned in Task 2.
- `2` already held when the fighter leaves the ground: earliest hop, no crash, no repeat trigger. Pinned in Task 2.
- A normal jump with `2` held must be unaffected. Pinned in Task 2.
- An air attack with no downward input must not change the rise. Pinned in Task 2.
- A landing, a hit or a tag must not leave a half-done ramp (`hop_stop_cnt`) for the next jump. Pinned in Task 2.
- An air jump or wall jump during a ramp must start a fresh ramp, not inherit the old one. Pinned in Tasks 3 and 4.

### Task 2: The hop on ground superjumps

**Files:**
- Modify: `include/pl_work.h` (carve one field from `unk_55d[]`), `src/pl_sub.c` (`pl_hop_ck`, hook in `pl_sjump_ctrl`, `cnt` in the trace), `src/pl_act.c` (reset `hop_stop_cnt` in `pl_land_set`, `act_air_recover`, `act_sjump`, the ground `act_jump`), `src/pl_team.c` (reset for the incoming `nw`, near lines 517 and 619), `include/pl_sub.h` (prototype)

**Interfaces:**
- Produces in `PLAYER_WORK`: `Uint8 hop_stop_cnt` (0 = not stopping; else ramp frames left) at `0x55d`; `Uint8 unk_55e` pads; the tail shrinks to `unk_55f[0x5a4 - 0x55f]` so the struct stays `0x5a4`.
- Produces: `void pl_hop_ck( PLAYER_WORK *pl_w )` in `src/pl_sub.c`, declared in `include/pl_sub.h`, and `#define HOP_STOP_FRAMES 5`.
- Consumes: `pl_sw_new` (`KEY_DOWN` also covers `1` and `3`), `cpu_flag`, `sjump_flag`, `spd.y`.

- [ ] **Step 1: Write the failing check.** Run the Task 1 harness for Ryu with `2 8` and then `down` held right after launch (e.g. add `+dur` 30 to a `down` press at launch + 1). Record the apex. Expected before the change: the same ~719 as the baseline (no hop). This is the failing check: the target is about 100-120.
- [ ] **Step 2: Add the field** in `include/pl_work.h` at `0x55d`: `hop_stop_cnt`, then `unk_55e`, then shrink the tail to `Uint8 unk_55f[0x5a4 - 0x55f]`. Add `_Static_assert( sizeof( PLAYER_WORK ) == 0x5a4, ... )` under `HOST_PORT` next to the struct. Add `hop_stop_cnt` to the `hop_trace` line.
- [ ] **Step 3: Implement `pl_hop_ck`.** Return at once if `!pl_w->sjump_flag || pl_w->cpu_flag`. If `hop_stop_cnt` is set: while `spd.y > 0`, set `spd.y *= ( cnt - 1 ) / cnt` (as Floats), then `cnt--`; if `spd.y <= 0` set `cnt = 0`. Otherwise, if `spd.y > 0` and `pl_sw_new & KEY_DOWN`, set `cnt = HOP_STOP_FRAMES` and apply the first ramp step in the same frame. Never raise `spd.y`. Only `KEY_DOWN` starts a stop; do not test any attack button.
- [ ] **Step 4: Hook it** in `pl_sjump_ctrl`: call `pl_hop_ck( pl_w )` right after the `sjump_flag` check, before the `sjump_cnt < 7` return and the forward/back return. This makes the hop run in each character's `sjump_move` too, so a downward input during an air attack still stops the rise. The attack alone does not (Step 6 checks this).
- [ ] **Step 5: Reset the ramp.** Set `hop_stop_cnt = 0` in `act_sjump` and the ground `act_jump` (`src/pl_act.c`), `pl_land_set`, `act_air_recover` and the tag-in code in `pl_team.c`. Then `Grep` every `sjump_flag = 1` write in `src/` (launcher-chase near `pl_main.c` line 1091, the counter tag-in near line 1854, the `act_change_out*` hops) and reset `hop_stop_cnt` at any site that begins a new rise. A fighter's own tag-out hop is scripted and not steered by the player: leave it, and say so in the report.
- [ ] **Step 6: Build, install and run the Step 1 check.** Expected: earliest-press apex about 100-120 units (record the real number). Then these runs, each recorded in the `hop_trace.ps1` header:
  - no `2`: apex equals the Task 1 baseline, and `sx` at the apex is identical to a run with a hop;
  - `2` pressed 10 frames after launch: apex higher than the earliest hop and lower than the baseline;
  - `2` pressed with no forward/back held (pure `2`): hop works;
  - `1` and `3`: hop works;
  - `2` held from before launch: earliest hop, `cnt` returns to 0, no re-trigger;
  - an air attack (`b1`) in the superjump with no downward input: the rise equals a superjump with the same attack and no hop (the attack does not halt it);
  - an air attack with `2` held: the rise stops;
  - a normal jump (`up` only) with `2` held after launch: apex equals a normal jump with no `2`;
  - land, then a normal jump with `2` held: unaffected (`sj=0` in the trace).
  Launcher-chase superjump, air recovery and tag-in superjump reach the hook through `act_sjump_air` (they set `sjump_flag` and fall back into it). If the headless run cannot reach them, confirm by reading the code path, and say in the report that they are unverified in-game.
  If the earliest hop is clearly under 90, raise `HOP_STOP_FRAMES` to 6 and re-measure; if still low, add a `hop_base_y` floor field and say so in the commit message.
- [ ] **Step 7: Commit** the struct change and `pl_hop_ck` with its hook: `git commit -m "feat: Super Hop - 1/2/3 eases a rising ground superjump to a stop over 5 frames"`.
